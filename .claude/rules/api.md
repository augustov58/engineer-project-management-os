# Rules for `apps/api`

Ground rules moved out of `AGENTS.md` on 2026-09-01, none rewritten. Claude Code loads this file when a
path in the frontmatter is read through the Read tool; from the shell, read it yourself. The rules that
apply to every path stay in `AGENTS.md`.

- Never call `new Date()` or `Date.now()` for a timestamp that gets persisted or aged, and never give such a column a database default — read the injected `TimeSource` (ADR-0022). Aging is tested by advancing a fake, never by sleeping.
- Tests drive the HTTP API against a real PostgreSQL and assert only on responses and subsequent reads. Build fixtures through the API, not by inserting rows.
- **Three** sanctioned exceptions, and no more without a line here. The first is a schema invariant no route can expose — which tables the migrations produced. `apps/api/test/schema.test.ts` reads `information_schema` through the harness's `tableNames()` and nothing else; it may not read domain data or write rows. It asserted "no `users` table exists" (ADR-0012) for twenty-one slices; since issue #105 it asserts that `users` and `sessions` **do** exist and that `roles`, `permissions` and `tenants` still do not (ADR-0055). The guard was replaced there and not deleted, deliberately: it fired, which is what it was for.
- The second sanctioned exception is a **vendor adapter's wire shape** (issue #109): `apps/api/test/vendors.test.ts` builds `azureDocumentIntelligenceOcr` and `azureSpeechTranscriber` over a substituted `fetch` and asserts the request this product composes and the reading it takes of a reply. No route exposes an adapter — the harness substitutes at the *port*, one level above, which is what every record test uses and what keeps "no test calls the vendor" true — so the URL, the api-version, the `Ocp-Apim-Subscription-Key` header, the inline `base64Source`, the multipart part names and the delete are reachable from nowhere else. It drives no HTTP and needs no PostgreSQL. `tools.test.ts` is **not** the precedent for this: it imports `src/helpers.ts` *and* drives the route through `startTestApi`. What this exception may not become is a second way to test a record; anything a route can answer is still asserted through the route.
- The third sanctioned exception is a **rule about the shape of the source** (issue #111): four tests in `apps/api/test/audit.test.ts` read `.ts` files off the disk rather than driving a route — that no writer of an audit line omits its actor or its subject, that nothing builds an actor out of a request body, that a line goes unattributed in one route and three commands and nowhere else, and that no model in `schema.prisma` carries a `created_by`. It is the shape `apps/web/test/session.test.ts` has given ADR-0020's one-door rule since issue #22, arriving on this side for the first time, and the trigger is the same: **the defect is a call site that exists, not a route that misbehaves**. The route sweep above it is exhaustive over routes and *cannot* be exhaustive over writers — `writeIssuance` serves two routes from one call site and `user reset` and `user enable` serve none — so three of the writers are invisible to it by construction. **How many there are is written down in `.claude/rules/memory.md` and nowhere else** — not here and not in `audit.test.ts`'s prose, where it was until issue #112 and came out rather than being bumped. Nor can a route sweep see an `audit()` reached through a wrapper that supplies its own actor, which would typecheck and would take the answer away from the boundary. What this exception may not become is a way to assert **behaviour** by reading source: every one of these is a rule about which code exists, and what a line actually records is asserted through the route beside them.
- **A rule that exists because of a size gets one fixture at that size** (ADR-0052), in the same test file as the rule — a byte limit, a pattern over a body, a bound on a list. One fixture and one assertion, not a performance suite: the point is that the rule is *run* once where it lives. `PAST_THE_STACK` in `test/harness.ts` is the one that exists — four and a half million characters, about 3.4 MiB — and `photos.test.ts` drives it through the store and through the 4n+1 refusal. It was written for issue #98, where a rule that was correct and tested had never been exercised at the size it exists for, because every other fixture here is a few hundred characters.
- **Release the held vendor, then wait for the run to stop writing.** A released
  `heldAgentRunService` or `heldTranscriber` is not a finished run: the vendor returns, then
  `underRunSession` revokes the run's session in a `finally` and the worker stamps
  `finishedAt` — two writes after the line that released it. A test that releases and returns
  leaves them racing its own `afterEach`, which force-closes the worker, disconnects Prisma
  and drops the database `WITH (FORCE)`; the abandoned writes reconnect into a database about
  to go, and the terminated connection is an **unhandled error that fails the whole run with
  every test in it passing**. That is what the first CI run did (issue #106): 614 passed,
  exit 1, `57P01`. It cannot be reproduced on a developer's machine, where the writes land
  before the teardown rather than after, so the rule is the only thing that catches it —
  `settles()` in `extractions.test.ts` is the shape.
- **A comparison across a frame boundary gets one test where the clock is not also the typed side** (ADR-0052): a typed time against a stamped one, a client instant against a server one. Either the `TimeSource` is the real clock, or it is injected with a **nonzero offset the test does not apply to the typed side** — because a test that supplies both sides of a comparison verifies the arithmetic and not the property. `photos.test.ts`'s *a photograph typed off the wall bins to a floor the clock stamped* is this side of it; the property itself is `apps/web/test/wall-clock.test.ts`, since ADR-0054 put the composing in the web app. This is not the aging rule above: aging still advances a fake, and never sleeps.
- Every route sits under `/v1` (ADR-0023), carried by the single `register` call in `apps/api/src/server.ts` rather than spelled into each path. That call is *one* call on purpose: the twenty route modules it invokes are plain functions and not Fastify plugins, because a plugin would be a second place a prefix could be added and the ADR's guarantee would become a convention (ADR-0033). (The count read "thirteen" until 2026-09-12 while `server.ts` said eighteen; only the number was stale.)
- A record type is a file under `apps/api/src/routes/`, named for the record and matching the test file that drives it (ADR-0033). Its schemas, its refusals that nothing else uses and its derive-on-read helpers live beside its routes. `server.ts` is the boundary and nothing else: the ajv setting, the gate in front of every route (ADR-0020), the prefix, and the list of record types. The gate is there for the reason the prefix is — it applies to all of them and to nothing narrower — and its implementation is a leaf, so `server.ts` gains a call and not a mechanism.
- **Every mutating route writes one `audit_entries` line, in the same transaction as its write** (story 106). Its `projectId` is **nullable** since issue #105: creating a user and signing in are the firm's mutations and not a job's, and both readers of the table filter on that column, so a firm-level line is absent from a project's audit rather than mislabelled in it. `audit.ts` is the one way a line is written and takes a `Prisma.TransactionClient`, so a route with nothing to open a transaction for opens one to say what it did; `at` is the caller's `timeSource.now()` and never read inside the leaf (ADR-0022). A refused write writes no line, and a no-op — the second archive, a resent recording — writes none either. `test/audit.test.ts` reads the routes Fastify registered and fails if a mutating one is missing from its list, which is what stops a route added later going unrecorded.
- `http.ts`, `refusals.ts`, `wire.ts`, `stream.ts`, `audit.ts`, `gate.ts`, `passwords.ts`, `users.ts`, `zone.ts`, `env.ts` and `vendor.ts` are **leaves** — they import Prisma and Fastify types and nothing from a route module, which is what stops `site-visits`, `photos` and `issues` importing each other in a cycle (ADR-0033). A thing used by exactly one record lives with that record and moves into a leaf only when a second record reaches for it: the SSE machinery was written inside `routes/voice.ts` and became `stream.ts` when a walk's reports reached for it (ADR-0035), which is exactly the trigger ADR-0033 names, and the 24 voice tests pass unchanged against it. `wire.ts` holds only the read shapes two or more records return; `withDerivedState` and `withLines` are used by one each and stayed put. Since issue #113 it also holds `inTheOrderTaken`, which is a **rule** rather than a shape and is the one exception: a finding's evidence is a union of two ordered lists (ADR-0056) and so has to be sorted in JavaScript, in `withSightings` and again in `report.ts`'s `evidenceFor`. The two unions stay separate, being narrowed differently; the comparator is shared because the API's answer and the issued document ordering the same photographs differently is the second-place-the-same-fact-lives failure, not a tidiness question. `zone.ts` (ADR-0054) arrived by the same trigger and was a leaf from its first line rather than after a move: reading an instant back in a project's zone is what `wire.ts` derives `visitedOn` with and what the report prints, so it had two readers before it had one. `env.ts` and `vendor.ts` (issue #109) are the newest two and show the trigger being applied in both directions: `requireEnv` moved out of `index.ts` when the two vendor adapters became its second and third readers, and the **poll helpers went back into `ocr.ts` after briefly sitting in `vendor.ts`** — the transcription adapter answers in one call and never polls, so they had one reader, and one reader is not the trigger. `vendor.ts` holds only `complaint` and `isAbort`. Neither holds a wall clock: a 2,000-page document and a ten-minute recording are not the same kind of wait, so each adapter names its own.
- `startTestApi({ worker: false })` **substitutes nothing** — it does not start a worker,
  which is a state production has too: the API up with a job still sitting in Redis. It is
  how *queued* became a state a test can stand in and look at, for work with no vendor seam
  to hold open the way `heldTranscriber` holds a transcription.
- No embedding, no vector column, no similarity ranking and **no full-text index**
  (ADR-0019). `schema.test.ts` asserts no `embeddings`, `document_embeddings` or
  `search_index` table, which is as far as ADR-0012's sanctioned exception reaches; a
  `tsvector` column would need that exception widened, and it deliberately is not.
